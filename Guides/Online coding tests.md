# Online coding tests

Many tech jobs send a timed coding test before the first interview, on a site such as CodeSignal or
HackerRank. Some now include an AI helper built into the test. This guide is mostly about
CodeSignal: its help pages are the most detailed.

How sure each point is: **maker's docs** (the test site's own help pages - how it's built to work,
not what every employer turns on) · **employer's own page** · **candidate accounts** (a few
people's own reports - not on our evidence scale, weaker than any survey) · **convention** (common
advice, no study).
Checked October 2026.

## What they are

- **One project or a few tasks, in the browser.** A code editor, a list of files, a terminal, a preview of
  the web page you build, and tests you run. *Maker's docs (CodeSignal).*
- **Parts that unlock in order.** Common format: 4 levels, each opens when the one before passes.
  Finishing all 4 isn't expected. *Maker's docs (CodeSignal).* Running out of time on the last level is
  common. *Candidate accounts.*
- **Length is the employer's choice.** Often 60-90 minutes. Read the invitation. *Maker's docs + candidate
  accounts.*
- **No pause.** Leave, and the clock keeps running. When time runs out, what you have is
  submitted. The clock starts after setup. *Maker's docs (CodeSignal).*
- **Hidden tests.** Some checks run only when you submit, not when you run the tests yourself.
  *Maker's docs (CodeSignal).*

## The rules

- **Proctored test = camera, microphone, your whole screen shared, and a photo ID.** You may be
  asked to close other tabs and programs. *Maker's docs (CodeSignal).*
- **Usual rules:** alone in the room, no phone or second device, no outside AI, no other editor.
  Some tests also ban scratch paper and web search. *Maker's docs (CodeSignal).*
- **The rules screen before you start is the final word.** Pages disagree on details, such as
  whether looking up syntax online is allowed. Each employer also sets its own. *Maker's docs.*
- **Breaking a rule can get your result thrown out.** CodeSignal reviews the recording within 1-3
  business days. A broken rule shows the employer "Proctoring Rejected" instead of a score. Common
  reasons: someone else in the room, leaving the camera's view, another device, searching online.
  *Maker's docs (CodeSignal).*
- **Employers say the same.** Anthropic allows AI to prepare, not during a live interview or a
  take-home unless told otherwise. *Employer's own page (2025).* Amazon reportedly warns that AI during
  interviews "may result in disqualification." *News report - the original wasn't reached.*
- **Pasting is noticed.** Pastes are marked on the replay the employer can watch, and copying the
  task text can be flagged. A flag isn't proof - people review it. *Maker's docs (CodeSignal).*

## Getting ready

- **Try the test site's own practice first.** CodeSignal has a free practice area that shows the
  same kinds of questions; employers don't see it. Learning the buttons there saves minutes on the
  day. *Maker's docs; candidate accounts.*
- **Check your computer the day before:** latest Chrome (or Firefox, Edge), camera, microphone, ID
  to hand, a steady connection (at least 500 Kb/s; ad blockers can slow it). No phone or tablet.
  *Maker's docs (CodeSignal).*
- **Plain room, one screen, phone away.** *Convention; the rules above.*
- **Don't leave it to the last day.** Candidates report freezes and tests submitted on a refresh.
  Only the employer can send a new link. *Candidate accounts; maker's docs.*
- **Need extra time for a disability?** Ask the employer before you start, in writing or out loud.
  How much you say is up to you. General information, not legal advice - the EEOC or your state's
  agency has the final word. *Law (EEOC guidance); maker's docs.*
- **Practise the same shape:** a small project, levels, a timer you don't pause. Say "I have an
  online coding test for job 3 - help me prepare". Job Finder makes up a practice task of the same
  kind. It never uses real test questions. *Convention.*

## On the day

- **First 5 minutes: look around.** Read the task, the file list, the tests, how to run them.
  *Candidate accounts.*
- **Pass the tests, then move on.** Simple and working beats clever and unfinished. Partial
  credit counts. *Maker's docs (points per test passed); candidate accounts.*
- **Run and submit often.** A refresh can lose unsaved work; earlier runs can be brought back.
  *Maker's docs; candidate accounts.*
- **Later parts change earlier code.** Rerun every test before you submit. *Convention.*

## The built-in AI helper

- **What it is:** on CodeSignal, a chat inside the editor ("Cosmo") that sees your code and won't
  give the whole answer. Some newer tests offer a coding agent instead. The employer chooses which,
  or none. *Maker's docs (CodeSignal).*
- **Everything you ask is recorded** and the employer can read it, along with a replay of your
  typing. *Maker's docs (CodeSignal).*
- **Ask small, clear questions:** what a requirement means, why a test fails (with the error), the
  syntax you half-remember. *Maker's docs (what it's for); convention.*
- **Check every answer by running the tests.** Candidates found it slow (about 30 seconds an answer),
  unable to run code, sometimes wrong. *Candidate accounts.*
- **Don't** ask it to solve a whole part, paste its code unread, or wait idle while it thinks.
  *Convention.*
- **Built-in only.** A helper inside the test doesn't make outside AI fair game. *Maker's docs.*

## Not during the real thing

Job Finder won't help while a test is open, even with "just a hint". The help itself is what gets a
result thrown out, whatever the odds of being noticed.
